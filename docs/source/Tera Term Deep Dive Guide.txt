Master Reference Guide and Technical Manual for Tera Term 4.x and 5.x
Tera Term remains an essential software utility across embedded systems engineering, infrastructure administration, and hardware verification. Originally created by Takashi Teranishi and maintained by the TeraTerm Project, the terminal emulator bridges legacy hardware protocols with modern network security and scriptable automation capabilities1.
The transition from Tera Term 4.x to Tera Term 5.x represents a major architectural redesign. Tera Term 4.x relied on a Win32 ANSI rendering core with external plugin hooks for international character translation and SSH operations1. Tera Term 5.x introduces a native UTF-16 text pipe, modernized Unicode rendering via the Windows Imaging Component (WIC), regular expression parsing using the Oniguruma engine, and upgraded API primitives for macro execution and host control2.
The core process ttermpro.exe houses the terminal emulation drivers, protocol engines, and plugin architecture2. Macro execution is delegated to an independent executable, ttpmacro.exe, which controls the primary terminal process using Windows Dynamic Data Exchange (DDE) messaging2. Low-level system access is provided through the Win32 Communications API for serial links and Winsock2 for network connections2. Modular capabilities can be added through Tera Term Extension (TTX) dynamic-link libraries, which hook into menu dispatchers, setup routines, and window event loops without requiring direct modifications to the source code2.
1. Core Architecture & Protocol Capabilities
Serial Communication Subsystem
Tera Term manages physical and virtual serial interfaces by opening low-level kernel handles via the Win32 Communications API (commlib.c)2. Channel characteristics are applied by configuring the system Device Control Block (DCB) structure using SetCommState(), while non-blocking operational timings are managed by passing non-zero limits to SetCommTimeouts().
Baud Rate Generation and Custom Divisors
Standard bit rates (such as 9600, 19200, 38400, 57600, and 115200 bps) map directly to default operating system driver clock dividers4. Modern embedded targets frequently require higher throughput to stream real-time diagnostic traces or flash large binary images, necessitating non-standard or arbitrary rates such as 230400, 460800, 921600, 1500000, or 3000000 bps6. Tera Term passes arbitrary integer baud rates directly to the underlying hardware controller through the /BAUD= or /SPEED= command-line switches or the BaudRate setting in TERATERM.INI4.

Framing Format and Flow Control Mechanics
* Data Bits: Configurable to 7-bit (legacy ASCII, telemetry streams) or 8-bit (raw binary payloads, UTF-8 byte sequences) framing formats4.
* Parity Verification: Supports None, Odd, Even, Mark (parity bit fixed at logic 1), or Space (parity bit fixed at logic 0) checking modes4.
* Stop Bits: Configurable for 1, 1.5, or 2 stop bit intervals to match receiver frame recovery windows4.
* Hardware RTS/CTS Flow Control: Uses Request to Send and Clear to Send signaling lines. When the host or target receive FIFO hits its high-water mark, it de-asserts its outbound control line, signaling the remote transmitter to pause send operations at the physical layer to prevent buffer overruns.
* Hardware DSR/DTR Flow Control: Data Set Ready and Data Terminal Ready handshaking monitors physical link availability and line state transitions.
* Software XON/XOFF Flow Control: Uses in-band ASCII control characters DC1 (0x11, XON) and DC3 (0x13, XOFF). Software flow control is unsuitable for raw binary transfers because binary payloads containing 0x11 or 0x13 values inadvertently trigger transmission pauses or resumes.
Character and Line Delays
To prevent input buffer overflow when sending ASCII data to low-power microcontrollers or unbuffered bootloader prompts, Tera Term provides character-level (/CDELAYPERCHAR=) and line-level (/CDELAYPERLINE=) pacing controls6. Tera Term 5.5.0+ introduces fine-grained script controls (setserialdelaychar, setserialdelayline) that allow microsecond-level delay injection following individual character byte writes or newline sequences (CR/LF), matching write latency requirements on bare-metal hardware7.

	Network Protocols & Transport Interfaces
Network connectivity is provided through Windows Sockets (Winsock2) integrated with the TTSSH security module2.
Secure Shell (SSH1 / SSH2) Architecture
The TTSSH module implements the SSH transport and authentication layers8. SSH1 is included for legacy compatibility but is disabled by default due to structural cryptographic weaknesses. SSH2 serves as the primary secure transport protocol.
* Cryptographic Key Support: TTSSH supports RSA, DSA, ECDSA, and Ed25519 key formats8. Ed25519 is preferred due to its high security margin and resistance to side-channel timing attacks.
* Authentication Flow: Supports password, interactive keyboard, and public key authentication using local key files (/keyfile=) or Windows SSH Agent forwarding (/ssh-A)8.
* X11 Forwarding: Enabled using /ssh-X8. TTSSH creates an X11 proxy socket on the remote host, tunneling graphical protocol packets back to a local display server (such as VcXsrv or Xming).
* Local Port Forwarding (/ssh-L): Binds a local TCP port and tunnels incoming connections through the SSH session to a target address and port accessible by the remote host.
* Remote Port Forwarding (/ssh-R): Binds a TCP port on the remote host and tunnels incoming connections back to a designated local address and port8.
* Dynamic Port Forwarding (/ssh-D): Turns Tera Term into a local SOCKS4/SOCKS5 proxy server8. Outbound traffic routed through this local port is dynamically tunneled through the SSH session8.
Telnet, Cygwin, and Raw TCP Sockets
* Telnet Protocol (RFC 854): Uses in-band escape sequences framed by Interpret as Command (IAC, 0xFF) bytes to negotiate session capabilities (such as Terminal Type, Suppress Go Ahead, and Window Size)6.
* Cygwin Subsystem Integration (cygterm): Connects directly to local Cygwin environments using POSIX pseudo-terminal (pty) pipes provided by cygterm.exe, bypassing SSH overhead for local shell tasks.
* Raw TCP/IP Sockets and Named Pipes: Opens unencrypted streaming connections to defined TCP ports or connects to local Windows Named Pipes using the \\.\pipe\<pipename> syntax, allowing direct debugging of hypervisors, emulators, and serial-over-IP converters6.
Terminal Emulation Modes & Text Rendering
Tera Term provides comprehensive support for standard DEC terminal specifications, vector graphic instructions, and multi-byte text encodings1.
Terminal Emulation Modes
* VT100 / VT220 / VT382 / VT420 / VT520: Full support for DEC escape sequences, absolute and relative cursor positioning, scrolling regions (DECSTBM), application keypad configurations, software character set selection (G0–G3 designators), and device status reports (DSR)1.
* TEK4010 Vector Graphics: Implements Tektronix 4010 vector decoding, translating graphical draw commands into system GDI drawing calls within a dedicated TEK window1.
Encodings and Structural Differences (Tera Term 4.x vs 5.x)
Tera Term 4.x used an ANSI byte-stream parser that relied on external lookup tables and hooks to decode multi-byte character sets like Shift-JIS, EUC-JP, or UTF-81.
Tera Term 5.x replaces this with a native UTF-16 Unicode parsing pipe9. incoming character streams are converted directly to UTF-16 code units and parsed using the Oniguruma regular expression engine2. Tera Term 5.6.0+ adds character-by-character width overrides within TERATERM.INI, enabling precise display cell sizing (single-width versus double-width) for ambiguous East Asian characters and custom unicode symbols3.
ANSI Color Systems and Alternate Screen Buffers
Tera Term parses standard 16-color SGR (Select Graphic Rendition) escape codes, 256-color extended palette maps (\x1b[38;5;<n>m), and 24-bit TrueColor sequences4. Support for alternate screen buffers (\x1b[?1049h / \x1b[?1049l) allows terminal applications like vim, htop, or tmux to render full-screen interactive interfaces without overwriting the primary scrollback buffer.

	Protocol Mechanics
XMODEM Family (Checksum, CRC, 1K)
The XMODEM protocol family relies on a stop-and-wait automatic repeat request (ARQ) structure.
* XMODEM-Checksum: Sends 128-byte data frames preceded by an SOH (0x01) header byte, a 1-byte packet sequence number, and a 1-byte bitwise inverted sequence number. Packets conclude with an 8-bit arithmetic checksum. The receiver validates the payload and returns ACK (0x06) or NAK (0x15).
* XMODEM-CRC: Replaces the 8-bit arithmetic checksum with a 16-bit CRC-CCITT polynomial (  ). The receiver requests CRC mode by returning ASCII 'C' (0x43) instead of NAK during initial handshaking.
* XMODEM-1K: Expands packet payloads to 1024 bytes per frame, marked by an STX (0x02) header byte. This payload expansion reduces acknowledgment overhead by   , improving throughput across high-speed links.
YMODEM Batch Protocol
YMODEM builds on XMODEM-1K by adding file metadata headers and multi-file batch transfers.
   * Header Packet (Block 0): Contains the null-terminated file name, decimal byte size, modification timestamp, and file permissions.
   * Batch Transfer Cycle: Once the receiver acknowledges Block 0, file data is transmitted using 1024-byte payload frames. Multiple files are sent sequentially, and the batch session concludes when the host sends an empty Block 0 frame.
ZMODEM Streaming Protocol
ZMODEM is a continuous streaming protocol designed for reliable, high-speed transfers.
   * Sliding Window Protocol: Unlike XMODEM and YMODEM, ZMODEM streams data continuously without pausing for per-packet acknowledgments. Acknowledgments are processed asynchronously while data continues to flow.
   * Auto-Start Reception: Transmits a unique ZRPKT header sequence (ZPAD/ZRPC). Tera Term detects this control framing and automatically launches its receiver module without requiring manual user interaction.
   * Checkpoint Resume (Crash Recovery): If an active transfer drops, ZMODEM negotiates a byte offset recovery position (ZCRCW) upon reconnecting. Data transfer resumes from the point of interruption, eliminating the need to retransmit verified bytes.
   * Data Integrity Verification: Uses 32-bit CRC frame checking for high reliability over noisy channels.
Kermit Protocol
Designed for restricted 7-bit channels, Kermit uses character escaping to encode 8-bit binary data into printable 7-bit ASCII strings. Kermit supports dynamic packet sizing, sliding window acknowledgments, and file attribute exchanges. Although its encoding overhead reduces throughput compared to 8-bit protocols, it remains reliable over legacy or 7-bit restricted links.
B-Plus and Quick-VAN Protocols
Legacy protocols originally developed for communications over public switched telephone networks (PSTN) and service networks1. B-Plus includes checksum validation and control code escaping to prevent accidental line disconnects during active data transfers4.
SCP (SSH Copy Protocol)
SCP transfers files securely over established SSH tunnels using the remote shell scp utility or SFTP subsystem (scpsend, scprecv)7. File privacy and data integrity are enforced by the underlying SSH transport layer encryption and Message Authentication Codes (MAC).
Embedded Flashing and Diagnostic Logging Workflows
Embedded Firmware Flashing via Bootloader
Updating embedded firmware over a serial console requires coordinating bootloader state transitions with host file transfer operations.
   1. Establish Target Connection: Open Tera Term and configure the serial communication properties (for example, 115200 baud, 8 data bits, no parity, 1 stop bit) to match the hardware target10.
   2. Interrupt Boot Sequence: Apply power or trigger a hardware reset on the target board while issuing break signals or key presses to break into the bootloader console (e.g., U-Boot>, loader>).
   3. Prepare Memory and Transfer Protocol: Clear target RAM/Flash memory and initiate the bootloader file transfer mode. For example, in U-Boot execute:
U-Boot> sf probe 0
U-Boot> loady 0x80000000 115200
The target bootloader will begin outputting continuous 'C' characters to signal its readiness to accept a YMODEM transfer.
   4. Initiate File Send in Tera Term: Open File > Transfer > YMODEM > Send..., choose the binary image (e.g., firmware_v2.1.bin), and start the transfer. Tera Term detects the target's readiness characters and transmits YMODEM Block 0 containing the file metadata, followed by the image payload frames.
   5. Monitor Transfer Progress: Tera Term displays a progress window showing byte counts, block numbers, and transmission error counts.
   6. Flash and Boot Binary: Once the transfer completes, write the binary payload from RAM into non-volatile flash storage and initiate execution:
U-Boot> sf erase 0x00000000 0x00100000
U-Boot> sf write 0x80000000 0x00000000 0x00100000
U-Boot> bootm 0x00000000
Crash Log Retrieval Workflow
      1. Configure Session Logging: Open File > Log... prior to reproducing system faults11.
      2. Enable Binary Capture: Check the Binary option in the log setup window to ensure raw binary values, escape sequences, and stack traces are captured without character set mapping or line-ending modifications (CRLF translations)4.
      3. Trigger Diagnostic Dump: Execute the kernel crash command or trigger a hardware watchdog panic on the target system (e.g., panic, sysrq, or assertion triggers).
      4. Flush and Close Log File: Once the dump finishes, select File > Log... and stop logging. This flushes all unwritten operating system buffers, saving the complete log file to disk.

Essential Communication Primitives
         * connect '<command_line>': Spawns or attaches to a ttermpro.exe session using specified command-line switches8.
         * disconnect: Terminates the active session link7.
         * send <arg1> <arg2> ...: Transmits text, numeric ASCII codes, or string variables without appending a newline12.
         * sendln <arg1> ...: Transmits data payloads followed by the configured newline sequence (CR, LF, or CRLF)4.
         * sendbreak: Sends a physical serial break signal or a Telnet IAC BREAK control sequence13.
         * wait <str1> [str2] ...: Pauses macro processing until one of the specified target strings appears in the incoming character stream7. The 1-based index of the matched string is saved to the result system variable. If the operation times out, result is set to 0.
         * waitregex <pattern1> ...: Evaluates incoming text against regular expressions using the Oniguruma engine2.
         * waitln <str1> ...: Suspends execution until an incoming line matches one of the target strings7.
         * flushrecv: Clears the internal macro receive buffer, purging old incoming data before running sensitive string matching operations7.
         * mpause <milliseconds>: Delays macro execution by a specified millisecond interval7.

Script 2: Automated Embedded Bootloader Verification Test






Code-Snippet
; ==============================================================================
; Script: bootloader_flash_test.ttl
; Purpose: Intercept bootloader, erase flash, download binary via YMODEM, verify
; ==============================================================================

TargetPort = '4'
BaudRate   = '115200'
ImageFile  = 'C:\builds\firmware_v5.2.bin'

; Connect to target COM Port
sprintf2 ConnCmd '/C=%s /BAUD=%s' TargetPort BaudRate
connect ConnCmd

; Clear buffer & interrupt boot countdown
flushrecv
timeout = 5

sendbreak
mpause 50
sendln ''
sendln ''

wait 'U-Boot>' 'Hit any key to stop autoboot'
if result == 0 then
   messagebox 'Failed to intercept target bootloader prompt.' 'Execution Aborted'
   disconnect
   end
endif

if result == 2 then
   sendln ''
   wait 'U-Boot>'
endif

; Step 1: Initialize Flash and Erase Partition
sendln 'sf probe 0'
wait 'SF: Detected' 'Failed'
if result == 2 then
   messagebox 'SPI Flash Initialization Failed.' 'Hardware Error'
   disconnect
   end
endif

sendln 'sf erase 0x00000000 0x00200000'
wait 'Erased' 'ERROR'
if result == 2 then
   messagebox 'Flash Erase Command Failed.' 'Flash Error'
   disconnect
   end
endif

; Step 2: Trigger Bootloader YMODEM Receive
sendln 'loady 0x80000000 115200'
wait 'C'

; Step 3: Launch Tera Term YMODEM Transmit
ymodemsend ImageFile

   messagebox 'YMODEM File Transmission Failed.' 'Protocol Error'
   disconnect
   end
endif

sendln 'sf write 0x80000000 0x00000000 0x00200000'
wait 'OK'

5. Troubleshooting & Performance Tuning
High-Speed Serial Latency and Buffer Overrun Resolution
Troubleshooting Dropped Bytes
At baud rates above 921600 bps, high interrupt frequencies or operating system scheduling delays can cause UART FIFO buffer overruns. This results in missing bytes, corrupted frames, or failed file transfers.
System Optimization Steps
         1. Reduce FTDI USB Driver Latency Timer: The default Windows FTDI USB driver delays forwarding received USB data packets to the operating system for 16 ms.
         * Open Device Manager > Ports (COM & LPT) > Properties > Advanced Settings.
         * Reduce the Latency Timer setting from 16 ms to 1 ms.
         2. Increase OS Serial FIFO Buffers: Open the serial port driver properties and expand the RX/TX hardware buffer allocations to 4096 bytes or higher.
         3. Enable Tera Term High-Speed Transmission Mode: Update TERATERM.INI to bypass internal inter-character delay throttling during file send operations4:
Ini, TOML
[Tera Term]
FileSendHighSpeedMode=on

         4. Configure Microsecond Pacing Delays: When sending commands to low-power targets without hardware flow control, add pacing delays in macro scripts to prevent receiver buffer overflows7:
Code-Snippet
setserialdelaychar 500                  ; Adds a 500-microsecond delay between sent characters
setserialdelayline 2000                 ; Adds a 2-millisecond delay after newline characters

The debug window displays active variable values, DDE handshake state changes, and evaluation steps for wait and waitregex commands in real time2.

Protocol and Display Fault Resolution
Hardware Flow Control Lockups
            * Symptom: Session output stops streaming, and the terminal stops responding to keyboard input.
            * Root Cause: FlowCtrl is configured for hardware RTS/CTS, but physical handshaking lines are floating or disconnected.
            * Resolution: Set FlowCtrl to none unless physical RTS/CTS wiring is connected4. If control lines are disconnected, CTS remains pulled low, permanently blocking outbound transmissions.
Character Encoding Artifacts (Mojibake)
            * Symptom: Terminal output displays garbled text or corrupted multibyte characters (e.g., â€”Ã©).
            * Root Cause: The target system's character encoding format does not match Tera Term's decoding configuration.
            * Resolution: Force matching character encodings using command-line arguments or session setup configurations6:
DOS
ttermpro.exe /KR=UTF8 /KT=UTF8

SSH Handshake Failures
               * Symptom: Connection attempts fail during cipher negotiation with errors such as "No matching cipher algorithm found" or failed key exchanges.
               * Root Cause: The remote server requires modern SSH ciphers or key exchange algorithms that are disabled in legacy TTSSH configurations, or the minimum Diffie-Hellman group size requirement is set too high9.
               * Resolution: Modify TERATERM.INI to update algorithm preference orders or lower the minimum allowed Diffie-Hellman group size when connecting to legacy systems9:
Ini, TOML
[TTSSH]
DhGroupMinInBit=1024                    ; Allows connections to legacy SSH servers using 1024-bit DH groups
